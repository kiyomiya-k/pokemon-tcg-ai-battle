## 課題

- エージェントは毎ターン、エンジンが提示する**合法手のリストから選ぶだけ**。実装の自由度より「どう選ぶか」が問われる
- 提出後は同レート帯の他エージェントと24時間自動対戦し、レーティングが更新される
- **アクティブなのは直近2提出のみ**。新規提出は古い提出を押し出す（この仕様が終盤の意思決定を支配する）
- 締切後も約2週間対戦が継続し、**最終順位は収束後の値**で決まる

## この解法の出発点：スコアは信用できない

**完全に同一の tar を7回提出**した結果:

```
855.6  779.2  777.9  764.2  760.8  729.9  687.4
n=7   mean=765.0   sd=51.4   range=168.2
```

主軸にしていた 855.6 は実力ではなく**分布の右端を1回引いただけ**だった。
以降、すべての意思決定を「LBの単発値」ではなく「ローカル400戦の信頼区間」に置き換えた。

## 解法の全体像

このコンペで公開されていたのはエージェント本体とラダーのメタ分析まで。
**自分のエージェントを評価するための道具は存在しなかったため、
ダンプ解析パーサ・400戦評価バッテリー・敗因解剖ツールはすべて自作した。**
本文の数字はすべてこの道具群の実測値である。

```
┌────────────────────────────┐
│ エピソードダンプ解析（自作） │ 4,729試合から両者の60枚と勝敗を抽出
│                            │ → 実在の「222戦・対Grimmsnarl 95%」リストを発掘
└──────────┬─────────────────┘
           │ ベースデッキ（56/60枚をそのまま採用）
           ▼
┌────────────────────────────┐    ┌──────────────────────────────┐
│ ルールベースパイロット 744行 │◄──│ カードDBからの機序分解        │
│ ・全合法手に点数+理由文字列  │    │ 打点 = 30+30×両者の場のエネ数 │
│ ・脅威検知6モード            │    │ Grimmsnarl(悪HP320)は草弱点   │
│ ・攻撃は意図的に最低点       │    │ → 相手のエネ加速が自分の燃料  │
└──────────┬─────────────────┘    └──────────────────────────────┘
           │ 変更1件ごと
           ▼
┌────────────────────────────┐
│ 評価バッテリー（自作・arena/）│ 各マッチアップ400戦・先攻後攻ペア
│ Wilson 95%信頼区間           │ → 下限が0.50を超えたときだけ採用
└────────────────────────────┘   （もっともらしい改良3案をここで棄却）
```

## 効いた工夫

**1. 勝率が「レート帯の関数」だと気づいた**

公開されていた帯別アーキタイプ分布（MYSO氏の分析）に、
**自分の実測マッチアップ勝率（各400戦）を掛け合わせた**。この組み合わせは誰も出していなかった。

| 帯 | 主な相手 | 自分の勝率 |
|---|---|---|
| 600–799（堀） | Lucario 24% / Alakazam 18–26% / Archaludon 3–28% | .410 / .733 / .352 |
| 900+（本拠地） | Grimmsnarl 43–61% | **.932** |

苦手が下の帯に、得意が上の帯に密集 = **勝率曲線が右上がり**。
必要なのは「全体的に強くすること」ではなく**谷を越える数ppだけ**だった。
実際 +6pp の押し上げで 652 → 853 まで自走した（線形改善ではなく脱出速度の突破）。

**2. コードで直せない負けを、デッキ4枠で直した**

自分のHP210に対して相手の技が220。この10点差はパイロットの判断では覆らない
（エネ破壊で攻撃を止める案は実測 ±0）。そこで**デッキ側を入れ替えた**。
自作パーサで発掘したベースリストに対して、動かしたのは次の4枠:

| カード | 元 | 変更後 | 狙い |
|---|---|---|---|
| Grow Grass Energy | 2 | **4** | エネ兼 +20HP。210→230 で Metal Defender 220 の確殺を破壊 |
| Lively Stadium | 2 | **4** | 基本ポケモン全員 +30HP。重ねて270 |
| 草エネルギー | 17 | 15 | HP付きエネが同じ仕事をする |
| Harlequin / Briar | 各1 | 0 | 枠の捻出 |

2枚では「引ければラッキー」、4枚で**デッキの性質**になる。**652 → 853.8**、全マッチアップ列が改善。

> パイロットが直せるのは判断。算数を直せるのはデッキだけ。

**3. カードテキストから見つけた16行（853.8 → 872.7 → 最終942.6）**

Crustle の特性は「ポケモンex からのダメージを完全無効化」。
こちらは Ogerpon ex 単騎 = **構造的に0ダメージ**なのに、パイロットは何百戦も殴り続けていた。
「Crustle への攻撃は0点」「Boss's Orders で別の的を引きずり出す」「先攻を取る」の16行で
最難関2マッチアップ +6pp。この提出（`policies/ogerpon2f`）が最終 942.6 の個体。

**4. 400戦CI判定が「もっともらしい劣化」を3回止めた**

- 捨て駒サイクル（Mega Brave の番に殻を差し出す）→ **−5pp** 棄却
- 非ex Ogerpon 2枚挿し → **−5pp** 棄却
- ミラー対策のベンチ貯金 → **.487** 棄却（`policies/ogerpon2g` として同梱。動く反例）

40戦ではCI幅±15ppで、このゲームの実効差（5〜10pp）は検出できない。400戦が下限だった。

**5. 締切4日前に凍結した**

480戦の敗因解剖（山札切れ 0/480、負けの大半はサイドレース1交換差の接戦）で
「直せる系統的欠陥は残っていない」と確認し、枠が残っている状態で提出を停止。
アクティブ=直近2提出の仕様上、追加提出は実証済みの主力を押し出すコインフリップにしかならない。
凍結した2本は収束期に 872.7/829.1 → **942.6/878.9** まで浮上した。

## ファイル構成

```
.
├── arena/                  # 自作評価ハーネス
│   ├── battle.py           #   1戦をエンジンで完走させる
│   ├── match.py            #   N戦を先攻後攻ペア×並列で回し Wilson CI を返す
│   ├── tournament.py       #   相手プール全体への総当たり評価
│   └── policy.py, deck.py  #   任意の main.py / deck.csv を方策として読み込む
└── policies/
    ├── ogerpon/            # v1  (LB 652)   最初の実装
    ├── ogerpon2c/          # 2c  (LB 853.8) デッキ側HP分岐点破壊
    ├── ogerpon2f/          # 2f  (LB 872.7 → 最終942.6) Crustle免疫+先攻 ★最終提出
    ├── ogerpon2g/          # 2g  (未提出)   ミラー対策 — 400戦で.487となり棄却した反例
    └── ogerpon2h/          # 2h  (最終878.9) +Briar。もう1つのアクティブ枠
```

対戦エンジン（`cg` パッケージ）はコンペ規約により再配布しないため含めていません。

```bash
kaggle competitions download -c pokemon-tcg-ai-battle -f "sample_submission/sample_submission/cg/..." 
# 取得した cg/ をリポジトリ直下に配置
```

## 実行例

```python
# PYTHONPATH=. で cg/ をリポジトリ直下に置いた状態で
from arena.match import PolicySpec, run_match, is_better

a = PolicySpec("2f", "policies/ogerpon2f/main.py", "policies/ogerpon2f/deck.csv")
b = PolicySpec("2c", "policies/ogerpon2c/main.py", "policies/ogerpon2c/deck.csv")
r = run_match(a, b, pairs=200, workers=8)   # 400戦（先攻後攻ペア）
print(r.winrate, (r.ci_low, r.ci_high), "SHIP" if is_better(r) else "REJECT")
```

Kaggle 上で同じ実験を再現できる公開データセットも用意しています:
